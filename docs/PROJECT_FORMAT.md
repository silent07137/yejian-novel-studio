# 页间工程文件规范 v2

`.sns` 保存单本书；`.snss` 保存整个书架。它们仅在用户主动导出时生成，均为 ZIP 容器，并非应用自动保存数据库。更改后缀不会改变文件内部类型。

## 容器

| 条目 | 内容 |
| --- | --- |
| `manifest.json` | 格式标识、版本、单书／多书类型、UTC 导出时间、正文摘要与图片清单 |
| `content.json` | 作者资料和全部作品数据：分卷、章节及标注、正文图片元数据、角色与关系、世界观、自定义字段、时间线、事件、情节连接、伏笔和灵感 |
| `assets/` | 封面、作者头像和正文图片的原始图片字节；不存在时不创建对应条目 |

清单的 `format` 为 `yejian-project`，`formatVersion` 为 `2`，`kind` 为 `book` 或 `collection`。`contentSha256` 和资源清单中的 `sha256` 用于导入前校验。正文以 Markdown 字符串保存，正文图片通过 `yejian-image:<图片 ID>` 引用；每张图片的字节在资源清单中以 `image:<图片 ID>` 登记。应用不会把原设备的绝对图片路径写进新文件，或按归档内路径直接解压。文件没有加密，分享前请注意其中包含作品全文、图片与作者信息。

导入时以经过校验的文件内部清单识别单书或多书，不以系统文件选择器返回的临时文件名判断。Android 可能按 MIME 类型把缓存副本改为 `.bin` 或 `.zip`；这不改变原工程文件，也不影响导入。

导入时先展示作品清单。若同 ID 作品已存在，必须明确确认才会替换；保存失败则保留原书架并清理本次写入的图片。应用外观、字体路径等设备设置不会由工程文件覆盖；空书架首次导入时可恢复作者资料。v1 ZIP 工程继续可读；旧版纯 JSON `.sns/.snss` 可导入文字与结构化数据，但无法恢复其指向旧设备路径的图片。

当前限制：单个工程文件最多 128 MB，解压后最多 256 MB；正文最多 64 MB，单张图片最多 32 MB。未来增加字段时保持向前兼容；遇到不支持的格式版本，应用会拒绝导入并提示升级，不会猜测解析。
