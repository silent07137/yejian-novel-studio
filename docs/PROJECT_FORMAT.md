# 页间工程文件规范 v3

`.sns` 保存单本书；`.snss` 保存整个书架。它们仅在用户主动导出时生成，均为 ZIP 容器，并非应用自动保存数据库。更改后缀不会改变文件内部类型。

## 容器

| 条目 | 内容 |
| --- | --- |
| `manifest.json` | 格式标识、版本、单书／多书类型、UTC 导出时间、每个分文件的 SHA-256 与字节数、图片清单 |
| `library.json` | 作者资料和各作品分文件的路径索引，不包含正文 |
| `profile.json` | 作者资料，不保存设备上的头像路径 |
| `books/N/book.json` | 一本书的名称、简介、时间等基本信息 |
| `books/N/volumes.json` | 分卷目录 |
| `books/N/chapters/M.json` | 单章标题、正文、状态、笔记、标注与图片元数据（包括显示宽度） |
| `books/N/roles.json` | 角色、人物关系、角色基础字段与自定义字段模板 |
| `books/N/worlds.json` | 世界观及其基础字段与自定义字段模板 |
| `books/N/story.json` | 时间线、事件、情节连接、伏笔与灵感 |
| `assets/` | 封面、作者头像和正文图片的原始图片字节；不存在时不创建对应条目 |

清单的 `format` 为 `yejian-project`，`formatVersion` 为 `3`，`kind` 为 `book` 或 `collection`。`files` 登记各 JSON 分文件的 `sha256` 和 `size`；资源清单中的 `sha256` 校验图片。新导出的文件不再包含集中式 `content.json`。正文以 Markdown 字符串保存，正文图片通过 `yejian-image:<图片 ID>` 引用；每张图片的字节在资源清单中以 `image:<图片 ID>` 登记。应用不会把原设备的绝对图片路径写进新文件，或按归档内路径直接解压。文件没有加密，分享前请注意其中包含作品全文、图片与作者信息。

`N`、`M` 是导出时的顺序编号；真实实体 ID 保存在各文件内。清单负责定位文件，名称本身不作为实体 ID。导入前检查文件路径、重复引用、尺寸、摘要及资源归属，拒绝未声明的文件。

## 本地保存与按需加载

导入时在后台解析并校验完整归档，再以事务写入现有 SQLite：目录、章节正文、角色、世界观、情节与章节附件分别保存到对应记录。不会把 ZIP 内容不加检查地解压到用户目录，也不会继续把作品全文当成一个大 JSON 文件保存。

书架和作品首页只读取书籍资料、分卷、章节目录及已保存的字数。选中章节时才读取该章正文、标注和图片；进入设定或情节时才读取对应模块。桌面写作参考栏与 AI 参考资料需要当前书的设定和情节，因此写作页会读取这几个模块，但不读取其他章节的正文。保存时保留未加载的数据，不用空列表或空正文覆盖它们。已读取的数据在当前会话中缓存；重新启动后恢复按需加载。导出为保证工程完整，会读取当前导出范围内的全部内容。

导入时以经过校验的文件内部清单识别单书或多书，不以系统文件选择器返回的临时文件名判断。Android 可能按 MIME 类型把缓存副本改为 `.bin` 或 `.zip`；这不改变原工程文件，也不影响导入。

导入时先展示作品清单。若同 ID 作品已存在，必须明确确认才会替换；保存失败则保留原书架并清理本次写入的图片。应用外观、字体路径等设备设置不会由工程文件覆盖；空书架首次导入时可恢复作者资料。v1/v2 ZIP 工程继续可读，重新导出时转换为 v3；旧版纯 JSON `.sns/.snss` 可导入文字与结构化数据，但无法恢复其指向旧设备路径的图片。旧应用不能读取 v3 新工程，因此分享给协同者前应确保他们已升级。

当前限制：单个工程文件最多 128 MB，解压后最多 256 MB；正文最多 64 MB，单张图片最多 32 MB。未来增加字段时保持向前兼容；遇到不支持的格式版本，应用会拒绝导入并提示升级，不会猜测解析。
